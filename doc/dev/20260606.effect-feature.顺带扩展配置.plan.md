# 20260606 功能与配置结构计划

## 结论

这个增强也好搞。

另外，命令名建议顺手统一：

- `qwq_team_color_dye` -> `qwq_bingo_team_color_dye`

这样三条命令风格一致：

- `qwq_bingo_team_color_dye`
- `qwq_bingo_sidebar`
- `qwq_bingo_effect`

当前插件里已经有两个定时任务：

- `team_color_dye`：现在固定 `10 tick`
- `bingo_sidebar`：现在固定 `10 tick`

后面准备加的 `bingo_effect` 也会是定时任务。

所以最合适的做法就是把这三个功能各自的刷新间隔都写进 `config.yml`，分别配置，默认值都给 `10`。

## 推荐的新配置结构

下面这版就是建议直接落地到 `config.yml` 的完整结构：

```yml
# 🎯 qwq-flytre-bingo-booster 配置

# 📢 日志级别 (Log Level): debug, info, warn, error, silent
log_level: info

# 🧾 命令名配置
commands:
  team_color_dye: qwq_bingo_team_color_dye
  bingo_sidebar: qwq_bingo_sidebar
  bingo_effect: qwq_bingo_effect

# 🚀 功能默认启用配置
features:
  team_color_dye:
    enabled_on_load: true
    refresh_interval_ticks: 10
  bingo_sidebar:
    enabled_on_load: true
    refresh_interval_ticks: 10
  bingo_effect:
    enabled_on_load: true
    refresh_interval_ticks: 10
    apply_duration_ticks: 30

# 💊 Bingo 常驻药水效果列表
bingo_effects:
  - enabled: true
    type: minecraft:fast_digging
    amplifier: 2
    hide_particles: true
  - enabled: true
    type: minecraft:night_vision
    amplifier: 1
    hide_particles: true
  - enabled: true
    type: minecraft:speed
    amplifier: 2
    hide_particles: true

# 👥 队伍检测配置
team_detection:
  # 🔍 检测方式: team 或 scoreboard
  # team       - 优先读玩家当前 scoreboard 上的原生 team，读不到时回退主 scoreboard
  # scoreboard - 读主计分板某个 objective 的分数值
  method: team
  # 📊 如果用 scoreboard 方式，指定主计分板 objective 名
  scoreboard_name: teamScore
```

## 这样拆的理由

### 0. 命令命名统一

当前名字：

- `qwq_team_color_dye`
- `qwq_bingo_sidebar`

不完全对齐。

统一后：

- `qwq_bingo_team_color_dye`
- `qwq_bingo_sidebar`
- `qwq_bingo_effect`

优点：

- 视觉上是一组命令
- README、`plugin.yml`、`config.yml` 更整齐
- 后续继续扩展 `bingo_*` 功能时命名规则更稳定

### 1. 每个功能单独控制刷新频率

这样最直观：

- `features.team_color_dye.refresh_interval_ticks`
- `features.bingo_sidebar.refresh_interval_ticks`
- `features.bingo_effect.refresh_interval_ticks`

以后要调性能时，不会互相影响。

### 2. `bingo_effect` 额外保留 `apply_duration_ticks`

这个值和刷新间隔不是一回事，建议分开。

比如默认：

- `refresh_interval_ticks: 10`
- `apply_duration_ticks: 30`

意思是：

- 每 `10 tick` 补一次效果
- 每次效果持续 `30 tick`

这样即使偶发卡顿，也不容易闪断。

### 3. `bingo_effects` 单独顶层

这样结构更清楚：

- `features.bingo_effect` 只放“功能开关”和“任务参数”
- `bingo_effects` 只放“效果条目列表”

后面读写配置也更干净。

## 各字段含义

### `features.team_color_dye`

- `enabled_on_load`
  - 插件加载后是否默认启用队伍染色
- `refresh_interval_ticks`
  - 队伍染色任务的执行周期
  - 默认 `10`

### `features.bingo_sidebar`

- `enabled_on_load`
  - 插件加载后是否默认启用侧边栏
- `refresh_interval_ticks`
  - 侧边栏刷新的周期
  - 默认 `10`

### `features.bingo_effect`

- `enabled_on_load`
  - 插件加载后是否默认启用常驻药水功能
- `refresh_interval_ticks`
  - 补药水的周期
  - 默认 `10`
- `apply_duration_ticks`
  - 每次补上的药水持续时间
  - 建议默认 `30`

### `bingo_effects`

每一项表示一个受插件管理的药水效果：

- `enabled`
  - 该效果是否生效
- `type`
  - 药水 ID，例如 `minecraft:night_vision`
- `amplifier`
  - Bukkit 内部等级值
- `hide_particles`
  - 是否隐藏粒子

## 默认效果说明

默认三条建议保留：

- 急迫 3
  - `minecraft:fast_digging`
  - `amplifier: 2`
- 夜视 2
  - `minecraft:night_vision`
  - `amplifier: 1`
- 迅捷 3
  - `minecraft:speed`
  - `amplifier: 2`

注意：

- `amplifier` 是内部值，不是玩家界面显示等级
- 所以显示等级 = `amplifier + 1`

## 代码层面怎么接

这个改动很顺手，主要就是把原来的固定 `10L` 改成读配置。

当前代码里：

- `TeamColorTask` 在主类里固定 `runTaskTimer(this, 0L, 10L)`
- `BingoSidebarTask` 在命令里固定 `runTaskTimer(plugin, 0L, 10L)`

后面改法就是：

- 默认命令名改成 `qwq_bingo_team_color_dye`
- 启动 `TeamColorTask` 时读取 `features.team_color_dye.refresh_interval_ticks`
- 启动 `BingoSidebarTask` 时读取 `features.bingo_sidebar.refresh_interval_ticks`
- 新增 `BingoEffectTask` 时读取 `features.bingo_effect.refresh_interval_ticks`

再加一个简单的保护：

- 如果配置值小于 `1`
- 自动回退到 `10`

## 建议

建议直接这样做，没什么技术阻碍，而且以后调性能很方便。

如果下一步继续实现，代码目标可以是：

- 队伍染色命令默认名统一成 `qwq_bingo_team_color_dye`
- 所有定时任务都改成从配置读取 tick 间隔
- 默认值统一 `10`
- `bingo_effect` 单独带 `apply_duration_ticks`
- `bingo_effects` 顶层存效果列表
